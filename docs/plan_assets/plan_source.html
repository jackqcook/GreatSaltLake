1. How this plan relates to the guide

The guide is the specification: it fixes what the model is (the equations, the compartments, the outputs and where the model stops), which method each component uses, which assumptions must be tested, and the order the work happens in. This plan adds only the how: where each input lives, what it takes to get it into the model, what "done" looks like at each stage, and where the available data falls short of what the guide's method needs.

Three rules follow from that:

  1. The five stages are the guide's build order, in the guide's sequence, with no stages added or merged.
  2. Methods are the guide's methods. Where the data can't yet support a guide method, the plan reports a data-readiness gap against that method; it does not quietly swap in a different method. The only alternatives used are the ones the guide itself names ("otherwise physics" for φ; "measured or bounded" for η; "particle bins or uncertainty bounds" for size effects).
  3. Fidelity is checkable. Appendix A maps every requirement in the guide to the section that satisfies it.

3. Stage 1 — 1 km grid and hourly inputs

Builds the spatial frame (lakebed cells i), the exposure term Xi(t), and every hourly forcing the later stages need. Guide method for exposure: geometry; no ML.

1.1 Build the 1 km lakebed grid

  • Cells i cover the lakebed, since the ODE is written "for each lakebed cell i". Use a projected equal-distance grid (UTM zone 12N, NAD83, matching the terrain data's horizontal datum) so every cell is exactly 1 km × 1 km.
  • Tag each cell with its arm/bay (north arm, south arm, Farmington Bay, Bear River Bay), because lake level is applied by arm.
  • The Salt Lake Valley boundary is needed as a receptor (it defines "entering the valley" for R and for the first-entry rule in Stage 3). The guide does not draw it, so it's listed under Decisions.

1.2 Exposure Xi(t) — geometry, no ML

Inputs (guide): USGS Saltair lake gauge; USGS terrain / Utah lidar.

  • Lake level by arm. Saltair (USGS 10010000) for the south arm and Great Salt Lake near Saline (USGS 10010100) for the north arm, both daily VERIFIED.
  • Terrain. The USGS half-meter topobathymetric elevation model (bathymetry 2002–2006 merged with 2016 Utah lidar) VERIFIED. Horizontal NAD83, vertical NAVD88, meters.
  • Method. For each cell, Xi(t) = fraction of the cell's area whose lakebed elevation is above that arm's water level at time t. Computed from the terrain pixels inside the cell, so exposure isn't reduced to one average elevation per cell.
Guide assumption: match elevation units and vertical datums This is a live issue, not a formality. The gauges report parameter 62614, which is NGVD 1929, feet VERIFIED; the terrain is NAVD 1988, meters. USGS's own conversion at the Saltair gauge (NOAA VERTCON) is NAVD88 = NGVD29 + 3.47586 ft VERIFIED. Stage 1 converts every gauge reading to NAVD88 meters before it touches the terrain, with a unit test on the conversion. (The earlier v1 code labelled these same gauge readings as NAVD88, which is exactly the error this assumption exists to catch.)

Terrain access (implementation detail)

The terrain is a single 34.0 GB GeoTIFF plus a 9.8 GB overview file on ScienceBase, stored behind tokenized S3 download links (the ScienceBase API / sciencebasepy issues them) VERIFIED. A 1 km cell doesn't need half-meter pixels: USGS itself resampled to 5 m to build its area tables. Plan: read a coarse overview level (about 5–25 m) rather than the full-resolution file, and record the resolution used, since the guide asks for a grid-resolution test.

Built-in validation target

USGS publishes elevation-area tables for the total lake and each of the four basins at 0.01 ft steps from 4,170 to 4,215 ft NAVD88, computed from this same terrain VERIFIED. Summing the wet area of each basin's cells at each level must reproduce those tables. That's a direct check on the grid, the basin tags, and the datum handling together.

4. Stage 2 — Field-calibrated emissions

Turns exposure and wind into emission βi(t) and tracks the sediment reservoir Si. The guide groups emission and chemistry together, so the arsenic fields cAs,i and ηi are also built here, ready for Stage 3.

2.1 Erodibility φi(t)

Inputs (guide): PI-SWERL field tests; moisture, crust, texture, satellite imagery. Method (guide): RF/XGBoost for φ with field labels; otherwise physics.

  • With field labels: PI-SWERL measurements become training labels; moisture, crust, texture and satellite features are the predictors; evaluation holds out whole field sites, not random samples.
  • Without them: physics-based φ from the same moisture/crust/texture inputs (the guide's "otherwise physics").
  • φ must be able to reach 0: the guide notes exposed ground may be crusted and non-erodible.

2.2 Threshold law: Ki, u*t,i, p

  • The guide calls the law approximate and says to calibrate it against field fluxes. PI-SWERL measures emission flux at controlled friction velocities, which is exactly the data that pins down u*t, p and K.
  • Calibrate K so β comes out in inverse-time units (guide).
  • K, p and u*t are calibrated against field fluxes, not tuned to PM10 monitors. That keeps emission independent of the Stage 4 validation data.

2.3 Sediment reservoir: Si(0) and Gi

  • The guide states initial S and replenishment G need independent estimates. Candidate independent evidence: supply-limited (depleting) behavior in repeated field flux tests, and surface-sediment surveys. Carry both as ranges into the uncertainty budget.
  • Integration detail: with coefficients held constant within each hour, dS/dt = G − βS has an exact exponential solution per step, which stays stable when β is large.

2.4 Arsenic: cAs,i and ηi

Inputs (guide): USGS sediment and dust chemistry; particle-size-matched samples. Method (guide): GP/kriging for cAs; measured or bounded η.

The dataset the guide links (USGS, "Dust and sediment data from Great Salt Lake and northern Utah, 2022") was checked VERIFIED:

What it containsImplication for the guide's method

Data-readiness gap (chemistry) The guide's GP/kriging method is kept. What's missing is lakebed sample density. Data-readiness gap (field calibration) No public PI-SWERL dataset for Great Salt Lake was located during this plan's source check. PI-SWERL results are the gating input for both the RF/XGBoost φ model and the threshold-law calibration, so locating published field campaigns (or requesting their data) is the first sourcing task of Stage 2.
Stage 2 is done when the threshold law is calibrated against field fluxes with parameter uncertainty; φ is evaluated on held-out field sites (or the physics φ is documented); Si(0) and Gi have independent estimates with ranges; and cAs,i (kriged, with variance) and η (measured or bounded) exist for every lakebed cell.

5. Stage 3 — Dispersion

Moves emitted dust from the lakebed to the valley. The guide specifies two steps: prototype with the ODE, then replace its airborne transfer equations with HYSPLIT dispersion driven by HRRR, using emissions βS. Guide method: HYSPLIT; no ML.

3.1 ODE prototype (first-order transfer)

  • Implement dI/dt, dR/dt and dRAs/dt with per-cell kV,i and kL,i, under the guide's stated assumption of well-mixed compartments and first-order transfer.
  • Purpose: prove the kg bookkeeping end to end. Checks: mass closes to numerical precision (sediment lost = airborne gained + valley arrival + removed); R never decreases; first valley entry is counted once (in the ODE, dust moved into R leaves I, so this holds by construction).
  • The prototype's kV, kL need a documented physical basis (for example cell-to-valley distance and how often HRRR winds blow toward the valley). They aren't tuned to PM10: R is cumulative arrival, not concentration.

3.2 Replace transfer with HYSPLIT driven by HRRR

  • Source term: βiSi per cell per hour. HYSPLIT then handles transport and deposition in place of kV and kL, and provides concentrations for monitor comparisons (guide).
  • HYSPLIT is public from NOAA READY; HRRR 3 km is available pre-formatted for HYSPLIT on a public AWS bucket, June 2015 onward VERIFIED.
  • Count first valley entry once. With particle output, flag each particle's first crossing into the valley boundary and add its mass to R (and RAs) only then, so dust that leaves and re-enters isn't double counted.
  • Run HYSPLIT and the ODE prototype over the same period and compare where their arrivals differ; the differences show what first-order transfer was missing.
Engineering constraint: HRRR data volume The HYSPLIT-ready HRRR files cover the whole continental US at about 3.4 GB per 6-hour file, roughly 14 GB per simulated day VERIFIED, and a spatial subset can't be pulled from them remotely. Two workable paths, still "HYSPLIT driven by HRRR": (a) run event windows from that archive, or (b) build a regional Utah file from the original HRRR output, which can be downloaded variable by variable and cropped, then converted with HYSPLIT's own conversion tools. Choose based on how many simulated days Stages 4–5 need.
Guide assumptions tested in Stage 3 Well-mixed compartments and first-order transfer (tested by comparing the ODE prototype against HYSPLIT) · count first valley entry once · R is cumulative arrival, not airborne concentration.
Stage 3 is done when the ODE prototype closes its mass balance; HYSPLIT runs from the hourly βS source; the first-entry rule is implemented and tested on a case with re-entering particles; and hourly concentrations exist at every validation monitor, along with R(t) and RAs(t).

6. Stage 4 — Held-out event and chemistry validation

Inputs (guide): EPA AQS / Utah DAQ PM10; independent plume and filter chemistry evidence. Method (guide): held-out events and locations.

  • Hold out both. Fix, before any comparison, a set of whole dust events and a set of whole monitor locations that are never used for calibration. Score the model on held-out events at held-out locations as well as each separately.
  • Compare like with like. PM10 monitors are compared with HYSPLIT concentrations at the monitor, never with R.
  • Attribution needs more than PM10. The guide states PM10 alone cannot identify GSL dust. Each validated event needs independent plume evidence that the dust came from the lakebed.
  • Arsenic needs chemistry. PM10 cannot validate arsenic (guide). Modeled arsenic is checked against filter chemistry. The USGS 2022 release's dust-trap arsenic (17 samples) is one independent line of evidence; it measures deposition over a collection period, so the comparison is against modeled deposition over the same period, not against concentration.
Stage 4 is done when held-out sets are fixed in advance; PM10 skill is reported for held-out events and locations; each validated event has independent plume evidence; and modeled arsenic is compared against independent chemistry with the chemistry uncertainty from Stage 2.

7. Stage 5 — Lake-level scenarios under identical weather

  • Hold the hourly HRRR weather fixed and change only lake level (by arm). The change flows through Xi → βi → emission → HYSPLIT → R and RAs.
  • Report arrival mass (R, RAs) and arrival rate (dR/dt, dRAs/dt) per scenario, each with its uncertainty range.
  • Scenario outputs stop at arrival. No exposure or health-effect estimates, as the guide specifies.
  • Scenario lake levels are listed under Decisions.

10. Decisions needed before building

The guide leaves these open. Each needs a choice (yours) before the stage that uses it:

  1. Salt Lake Valley boundary (Stage 1, used in Stage 3). Defines "entering the valley" for R and the first-entry rule.
  2. Lake-level source for Farmington Bay and Bear River Bay (Stage 1). The two USGS gauges cover the north and south arms; these bays are partly separated by causeways and dikes.
  3. Particle bins or uncertainty bounds for size-dependent transport and enrichment (Stage 2–3). The guide allows either.
  4. Sourcing path for field data (Stage 2): published PI-SWERL campaigns, data requests, or new fieldwork; same for more lakebed chemistry.
  5. Simulation period and HRRR strategy (Stage 3): event windows from the HYSPLIT-ready archive, or a regional file built from raw HRRR.
  6. Scenario lake levels (Stage 5).

Appendix B — What changed from the earlier V2 plan

  • Structure: nine self-defined phases replaced by the guide's five-stage build order.
  • Monitor comparison: the earlier plan proposed converting R into a concentration with an assumed mixing volume. Removed: the guide says R is not concentration, and monitor comparisons use HYSPLIT concentrations.
  • Arsenic: the earlier plan led with literature placeholder values. Now the guide's GP/kriging method stands, with the lack of lakebed samples reported as a data gap; η is bounded only as the guide allows.
  • Erodibility: physics φ is no longer presented as the default; it's the guide's fallback when field labels are unavailable.
  • Design drivers: the earlier plan was shaped around reusing v1 code. This plan is shaped only by the guide; code reuse is an implementation convenience, not a design input.
  • New, verified facts added: gauge datum (NGVD29), terrain datum (NAVD88 m), the official offset, north-arm gauge, terrain file sizes and access, contents of the guide's chemistry dataset, HRRR friction velocity and data volume.
